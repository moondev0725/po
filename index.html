프로젝트 개요

NEXT DEBUT는 연습생 육성 게임, 도감, 뽑기, 카드 강화, 팬미팅, 커뮤니티, 결제, 관리자 기능을 하나의 서비스 흐름으로 연결한 웹 프로젝트입니다. 저는 팀장으로서 페이지 전체 틀과 주요 도메인 구조를 먼저 정리하고, 기능이 많아져도 사용자 흐름이 끊기지 않도록 서비스 구조를 설계하며 프로젝트를 주도했습니다.

담당 역할

팀장으로서 프로젝트 방향과 화면 흐름을 정리했고, 페이지 전체 공통 레이아웃, 관리자 페이지, 회원가입 및 로그인, 인게임 채팅과 ML 기반 입력 처리, BGM, 메인 페이지 공동 작업, 도감 페이지, 가이드 페이지, 뽑기, 카드 강화 기능을 직접 구현했습니다. 또한 Java와 Python이 설치되지 않은 환경에서도 실행할 수 있도록 포터블 실행 구조와 런처를 구성해 배포 편의성까지 고려했습니다.

핵심 기여

가장 큰 기여는 팀장으로서 서비스 전체 틀과 사용자 흐름을 먼저 설계하고, 게임 플레이, 도감, 뽑기/강화, 커뮤니티, 결제, 관리자 기능이 하나의 경험으로 자연스럽게 이어지도록 구조화한 뒤 핵심 기능을 직접 구현한 점입니다.

주요 구현 기능

  • 회원가입, 로그인, OAuth2 기반 인증 흐름 및 계정 관리 기능 구현
  • 메인 페이지 공동 작업 및 주요 진입 흐름 구성

  • 캐릭터 데이터베이스 기반 도감 페이지 및 수집형 구조 구현
  • 가이드 페이지를 통한 서비스 이해 흐름 정리
  • 뽑기, 포토카드, 카드 강화, 상점 구매 흐름 구현
  • 관리자 대시보드, 회원 관리, 운영 확인 기능 구현
  • Java 및 Python 미설치 환경에서도 실행 가능하도록 포터블 런처 및 실행 구조 구성

Java 21 Spring Boot Spring Security OAuth2 JPA JSP JSTL JavaScript Gradle WebSocket KakaoPay H2 FastAPI scikit-learn Python ML PowerShell

배포 / 실행 환경 구성

단순히 기능 구현에 그치지 않고, 사용자가 별도의 Java나 Python 실행 환경을 직접 설치하지 않아도 프로젝트를 실행할 수 있도록 런처와 포터블 실행 구조를 구성했습니다. 이를 통해 실제 실행과 배포 과정까지 고려하며 서비스 완성도를 높이고자 했습니다.

트러블슈팅 / 설계 포인트

  • 게임, 커뮤니티, 수집/강화, 운영 기능이 한 프로젝트 안에 함께 존재해 도메인 간 책임이 섞이지 않도록 계층과 역할을 명확히 분리했습니다.
  • 기능 수가 많아질수록 화면 추가보다 전체 흐름 정리가 더 중요하다고 판단해 공통 레이아웃과 사용자 이동 흐름을 먼저 설계했습니다.
  • 인게임 채팅과 ML 입력 해석 기능은 단순 연결이 아니라 실제 플레이 흐름 안에서 자연스럽게 동작하도록 구조를 조정했습니다.
  • 사용자 기능과 관리자 기능이 충돌하지 않도록 운영용 흐름을 별도로 구성해 관리 효율을 높였습니다.
  • 실행 환경 의존도를 줄이기 위해 Java와 Python이 설치되지 않은 PC에서도 동작할 수 있도록 포터블 런처 구조를 구성했습니다.

프로젝트 개요

Moms Log는 육아 정보 탐색, 공감형 커뮤니티, 지역 기반 소통을 하나의 플랫폼 안에서 연결한 서비스입니다. 정보성 콘텐츠와 커뮤니티 기능이 동시에 커지는 구조라서, 사용자가 원하는 정보에 빠르게 도달할 수 있는 데이터 구조와 카테고리 설계가 중요했습니다.

담당 역할

Django 기반 커뮤니티 기능과 정보형 콘텐츠 구조를 중심으로 게시판, 반응, 위치 기반 요소, 실시간 소통 기능이 확장 가능한 형태로 연결되도록 구현했습니다.

핵심 기여

정보 탐색과 커뮤니티 이용 흐름이 따로 놀지 않도록 게시판, 카테고리, 위치 정보 구조를 하나의 사용자 경험으로 정리했습니다.

주요 기능

  • 회원가입, 로그인, 프로필 관리, 포인트 및 등급 관리 기능 구현
  • 자유게시판, 공감형 반응, 댓글, 첨부파일, 지역 기반 게시글 분류 기능 구현
  • 월령/발달 정보 중심의 육아 정보 게시판 구조 설계
  • 레시피 공유와 단계별 조리 콘텐츠 UI/데이터 구조 구현
  • 카카오 지도 기반 지역 정보와 위치 좌표 활용 기능 구현
  • 챗봇 및 추천형 기능으로 확장 가능한 구조 경험

기술 스택

Python Django HTML CSS JavaScript SQLite KakaoMap

트러블슈팅 / 배운 점

  • 게시판 성격이 다양해질수록 모델과 카테고리 구조가 복잡해져, 탐색 흐름이 무너지지 않도록 기능별 데이터 구조를 더 명확히 나눴습니다.
  • 실시간 채팅은 연결 자체보다 운영 정책과 예외 상황 설계가 더 중요하다는 점을 경험했고, 기능보다 사용 시나리오를 먼저 보게 되었습니다.
  • 설정 파일, 데이터 파일, 민감정보가 함께 섞이지 않도록 분리하면서 배포와 유지보수 관점의 구조 설계 중요성을 체감했습니다.

WHAT I LEARNED

프로젝트를 하며
중요하게 느낀 것

프로젝트를 진행하며 단순히 기능을 하나씩 구현하는 것보다, 사용자가 로그인하고, 플레이하고, 수집하고, 결제하고, 커뮤니티를 이용하는 전 과정이 하나의 흐름으로 자연스럽게 이어지도록 설계하는 일이 더 중요하다는 점을 체감했습니다.

특히 기능이 늘어날수록 코드와 설정, 도메인 책임이 뒤섞이며 관리와 확장이 어려워지는 문제를 경험했고, 이를 통해 역할과 책임을 분리하는 구조 설계의 중요성을 분명히 이해하게 되었습니다.

이 경험 이후에는 기능 구현 이전에 서비스 흐름, 도메인 구조, 예외 상황, 실행 환경까지 먼저 정리하고, 이를 유지보수 가능한 형태로 연결하는 방식을 개발의 기준으로 삼게 되었습니다.

그래서 저는 단순히 기능을 구현한 경험보다, 아이디어를 실제 사용자 경험과 구조로 구체화하고 끝까지 완성해낸 경험을 제 강점으로 보여주고 싶습니다.
